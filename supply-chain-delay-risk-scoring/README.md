# 📦 공급망 배송 지연 리스크 스코어링

> 주문 시점 정보만으로 배송 지연 가능성을 예측하고,  
> 각 주문의 리스크 스코어(0~100)를 산출하는 분류 모델 구축 프로젝트

<br>

## 📌 프로젝트 개요

| 항목 | 내용 |
|------|------|
| 분석 목적 | 배송 지연 위험 주문을 출고 전 단계에서 사전 식별 |
| 데이터 | DataCo Smart Supply Chain Dataset (Kaggle) |
| 데이터 규모 | 180,519건 / 53개 원본 컬럼 |
| 타겟 변수 | `Late_delivery_risk` (1 = 지연, 0 = 정상) |
| 사용 기술 | Python, Pandas, Scikit-learn, XGBoost, Matplotlib, Seaborn, Streamlit |

<br>

## 🎯 문제 정의

이커머스 공급망에서 **전체 주문의 54.8%가 배송 지연**되는 상황을 확인했다.

지연이 발생한 후 사후 대응하는 방식으로는 고객 불만과 운영 비용을 줄이기 어렵다.  
따라서 본 프로젝트는 **“출고 전 단계에서 지연 가능성이 높은 주문을 미리 파악할 수 있을까?”** 라는 질문에서 시작했다.

**목표**

- 주문 시점에 알 수 있는 정보만으로 배송 지연 여부를 예측
- 각 주문에 대한 리스크 스코어(0~100)를 산출
- 고위험 주문을 우선 모니터링 대상으로 분류해 출고 전 대응 우선순위를 제안

<br>

## 🔍 분석 과정 요약

### 1. EDA — 문제 구조 파악

- 전체 주문의 **54.8%가 배송 지연**으로 분류되어, 배송 지연이 데이터상 구조적으로 큰 문제임을 확인했다.
- 배송 방식별 실제 지연율은 `First Class`, `Second Class`에서 높게 나타났다.
- `Days for shipping (real)`은 타겟과 강한 관계를 보였지만, 배송 완료 후에야 알 수 있는 정보이므로 모델 피처에서 제거해야 하는 **데이터 누수 후보**로 판단했다.

배송 방식별 실제 지연율은 다음과 같다.

| 배송 방식 | 실제 지연율 |
|-----------|------------:|
| First Class | 약 95.3% |
| Second Class | 약 76.6% |
| Same Day | 약 45.7% |
| Standard Class | 약 38.1% |

> `Standard Class`는 주문 수가 많아 운영상 중요하지만, 지연율 자체가 가장 높은 배송 방식은 아니다.  
> 고위험 비율 해석은 “배송 방식별 실제 지연율”과 “모델이 산출한 고위험 스코어 분포”를 구분해서 설명해야 한다.

### 2. 전처리 — 데이터 누수 방지

초기 전처리에서 `Days for shipping (real)`을 피처로 포함했을 때 모델 성능이 비정상적으로 높게 나왔다.  
이는 배송이 완료된 뒤에야 알 수 있는 정보가 포함된 **데이터 누수(Data Leakage)** 문제였다.

> 실전에서 주문 시점 예측 모델이 목표이므로, 미래 정보가 섞이면 실제로 쓸 수 없는 모델이 된다.

**제거한 누수 컬럼**

| 제거 변수 | 제거 이유 |
|-----------|-----------|
| `Days for shipping (real)` | 실제 배송 소요일 — 배송 완료 후 확인 가능 |
| `Delivery Status` | 배송 결과 상태 — 타겟과 직접 연결 |
| `shipping_delay` | 실제일 - 예정일 파생 변수 — 배송 완료 후에만 계산 가능 |

**전처리 주요 내용**

- 개인정보 컬럼 제거
- ID, 이미지 URL, 위경도 등 모델 피처로 부적절한 컬럼 제거
- 날짜 변수에서 연/월/일/요일 파생 변수 생성
- 범주형 변수 One-Hot Encoding 적용
- 주문 시점에 알 수 있는 정보 중심으로 피처 구성

**해석 주의: `Order Status`**

`Order Status`는 주문 시점 운영 정보로 활용 가능할 수 있지만, `CANCELED`, `SUSPECTED_FRAUD`와 같은 상태는 일반적인 배송 지연과 다른 처리 경로를 가질 수 있다.  
따라서 현재 모델에서는 피처로 사용하되, 포트폴리오 설명에서는 “운영 시점에 확인 가능한 주문 상태 변수로 제한 사용했으며, 사기 의심/취소 주문은 별도 운영 리스크로 분리 검토가 필요하다”고 설명한다.

### 3. 모델링 — 베이스라인 → 개선 모델

단순한 모델로 베이스라인을 먼저 잡고, XGBoost로 성능을 개선했다.

| 모델 | Accuracy | F1 Score | ROC-AUC |
|------|---------:|---------:|--------:|
| Logistic Regression | 71.1% | 0.675 | 0.770 |
| **XGBoost** | **71.8%** | **0.693** | **0.792** |

XGBoost는 ROC-AUC 약 **0.79**를 기록해 랜덤 분류기(0.5)보다 유의미하게 높은 구분 성능을 보였다.  
다만 AUC 0.79는 완전 자동 의사결정보다는 **고위험 주문을 우선 점검하는 보조 의사결정 도구**로 해석하는 것이 적절하다.

### 4. 리스크 스코어 검증

모델 출력 확률을 0~100점으로 변환해 리스크 스코어를 만들었다.

| 스코어 | 위험 등급 | 운영 해석 |
|--------|----------|-----------|
| 0 ~ 39 | 낮음 | 정상 배송 가능성이 상대적으로 높음 |
| 40 ~ 69 | 보통 | 모니터링 필요 |
| 70 ~ 100 | 높음 | 출고 전 우선 점검 후보 |

테스트 데이터 기준, **리스크 스코어 70점 이상 고위험 주문군의 실제 지연율은 약 89.1%**로 나타났다.  
전체 평균 지연율 54.8%보다 높기 때문에, 리스크 스코어는 출고 전 우선 모니터링 대상을 좁히는 데 활용 가능하다.

| 기준 | Precision | Recall | F1 Score | 해석 |
|------|----------:|-------:|---------:|------|
| 40점 이상 | 약 0.679 | 약 0.796 | 약 0.733 | 넓게 잡아 많은 지연 주문을 포착 |
| 50점 이상 | 약 0.858 | 약 0.582 | 약 0.693 | 기본 분류 기준 |
| 70점 이상 | 약 0.891 | 약 0.542 | 약 0.674 | 고위험 주문을 정밀하게 선별 |

> 70점 이상 기준은 모든 지연 주문을 잡는 목적이 아니라, 실제로 지연될 가능성이 높은 주문을 우선 점검하기 위한 기준이다.

## 💡 주요 인사이트

### Insight 1. 배송 지연은 특정 배송 방식에서 더 크게 나타났다.

실제 지연율 기준으로 `First Class`, `Second Class`에서 지연 위험이 높았다.  
이는 빠른 배송을 약속한 주문일수록 운영 여유가 적어 지연으로 이어질 가능성이 높다는 해석으로 연결된다.

### Insight 2. 예정 배송 소요일은 모델이 가장 강하게 활용한 변수였다.

`Days for shipment (scheduled)`는 주문 시점에 확인 가능한 변수이면서 지연 여부와 강하게 연결된다.  
특히 예정 배송일이 짧은 주문은 출고 전 단계에서 우선 점검할 필요가 있다.

### Insight 3. 리스크 스코어 70점 이상 주문군은 실제 지연율이 높았다.

고위험 주문군의 실제 지연율이 전체 평균보다 높게 나타나, 모델 스코어가 운영 우선순위 선별에 활용될 수 있음을 확인했다.

### Insight 4. 리스크 스코어는 운영 액션의 우선순위 기준으로 활용할 수 있다.

리스크 스코어는 배송 방식을 무조건 업그레이드하라는 의미가 아니라, 다음과 같은 운영 액션 후보를 좁히기 위한 기준이다.

- 출고 우선순위 점검
- 예상 배송일 재검토
- 고위험 주문 모니터링 강화
- 지연 가능성이 높은 주문에 대한 사전 안내 검토
- 배송 방식·지역·카테고리별 운영 리포팅
