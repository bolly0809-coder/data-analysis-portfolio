# 04 Validation Decision Log

## 결정 1. 01~03 결과물을 통합 검증

- 문제: 각 노트북이 개별적으로는 잘 구성되어도, 전체 포트폴리오 관점에서 사용 가능한지 확인이 필요함
- 처리: 01, 02, 03 outputs를 모두 불러와 통합 검증 테이블 생성
- 이유: 전처리 결과의 일관성과 해석 가능 범위를 한눈에 보여주기 위함

## 결정 2. PASS / CHECK / LIMITATION 기준 사용

- 문제: 전처리 결과를 모두 성공/실패로만 나누면 실제 데이터의 한계를 설명하기 어려움
- 처리: PASS, CHECK, LIMITATION 세 단계로 검증 상태 구분
- 이유: 실무 데이터에는 결측, 미매칭, 중복 후보가 존재할 수 있으므로 해석상 주의점을 분리해 설명하기 위함

## 결정 3. 리뷰 텍스트는 READY_WITH_LIMITATION으로 판정

- 문제: 실제 리뷰와 실제 사전을 사용했지만, 사전 기반 방식은 문맥 반전·비꼼·미등록 표현을 완벽히 처리하지 못함
- 처리: 사용 가능하지만 한계를 명시해야 하는 자료로 판정
- 이유: 포트폴리오에서 과장하지 않고 분석 범위를 정직하게 설명하기 위함

## 결정 4. 04를 분석 결과가 아닌 QA 리포트로 정의

- 문제: 04가 새로운 분석처럼 보이면 역할이 불분명해짐
- 처리: 전처리 통합 검증 리포트로 명확히 정의
- 이유: 01~03을 지원하는 보조 검증 자료로 사용하는 것이 적절하기 때문
