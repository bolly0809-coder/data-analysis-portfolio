# 04 Interview Talking Points

## Q1. 전처리 결과를 어떻게 검증했나요?

전처리 후에는 결과 파일을 다시 불러와 행 수, 결측치, 중복 key, 기준 단위가 의도와 맞는지 확인했습니다. 상품 데이터는 랭킹 기준 데이터와 고유 상품 기준 데이터가 잘 분리되었는지 봤고, Olist 데이터는 주문 단위와 상품 단위 base table의 key 중복 여부를 확인했습니다. 리뷰 텍스트는 카테고리 매칭률과 미매칭 샘플을 확인해 사전 기반 방식의 커버리지를 점검했습니다.

## Q2. PASS / CHECK / LIMITATION 기준을 둔 이유는 무엇인가요?

실제 데이터는 항상 완벽하지 않기 때문에 모든 결과를 성공/실패로만 나누기 어렵습니다. 바로 사용할 수 있는 항목은 PASS, 해석상 확인이 필요한 항목은 CHECK, 분석 한계로 명시해야 하는 항목은 LIMITATION으로 구분했습니다. 이 기준을 통해 포트폴리오에서 과장하지 않고 데이터의 해석 범위를 설명할 수 있습니다.

## Q3. 리뷰 텍스트 전처리를 READY_WITH_LIMITATION으로 둔 이유는 무엇인가요?

실제 리뷰 원문과 실제 사전을 사용했지만, 사전 기반 매핑은 비꼼, 문맥 반전, 사전에 없는 표현을 완벽히 처리하지 못합니다. 그래서 결과를 자동 판정 지표가 아니라 추천/진단 판단을 보조하는 리뷰 신호로 설명해야 한다고 봤습니다.

## Q4. 이 검증 노트북이 보여주는 역량은 무엇인가요?

단순히 pandas 코드를 실행하는 것이 아니라, 전처리 결과가 분석 가능한 구조인지 검증하고, 각 결과를 어떤 범위에서 해석해야 하는지 판단하는 역량을 보여줍니다.
