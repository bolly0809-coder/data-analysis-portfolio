# 02 Interview Talking Points

## Q1. Olist 프로젝트에서 JOIN할 때 가장 주의한 점은 무엇인가요?

Olist 데이터는 주문, 상품, 결제, 리뷰 테이블의 기준 단위가 서로 달라서 무작정 JOIN하면 결제금액이나 리뷰 점수가 중복 집계될 수 있습니다. 그래서 결제와 리뷰는 주문 단위로 먼저 사전 집계한 뒤 주문 테이블에 결합했고, 월별 KPI와 카테고리 매출 분석에 서로 다른 base table을 사용했습니다.

## Q2. 주문 단위 base table과 상품 단위 base table을 왜 분리했나요?

월별 주문 수, 매출, 객단가, 배송 지연율은 주문 1건 기준으로 계산해야 합니다. 반면 카테고리별 매출, 상품 가격, 판매자 분석은 주문상품 1행 기준으로 계산해야 합니다. 기준 단위가 다르기 때문에 하나의 테이블에서 모든 지표를 계산하면 중복 집계 위험이 있어 `order_base_delivered`와 `order_item_base_delivered`를 분리했습니다.

## Q3. 전처리에서 base table 설계가 왜 중요한가요?

분석 질문에 맞는 기준 단위를 정하지 않으면 지표가 왜곡될 수 있습니다. 예를 들어 주문 1건에 상품이 여러 개 있을 때 상품 단위 테이블로 주문 수를 세면 주문 수가 과대 집계될 수 있습니다. 그래서 전처리 단계에서 grain을 먼저 정의하고, JOIN 전후 행 수와 key 중복 여부를 확인했습니다.

## Q4. 이 노트북이 보여주는 핵심 역량은 무엇인가요?

단순히 pandas나 SQL로 JOIN할 수 있다는 것이 아니라, 테이블의 관계와 기준 단위를 이해하고 분석 목적에 맞는 데이터셋을 설계할 수 있다는 점입니다.
