# 03 Text Preprocessing Decision Log

## 결정 1. 실제 잡플래닛 리뷰 원문 사용

- 문제: 임의 리뷰 데이터는 실제 프로젝트의 전처리 역량을 충분히 보여주지 못함
- 처리: 실제 잡플래닛 크롤링 결과 일부를 사용
- 이유: 포트폴리오 증거 자료는 실제 프로젝트 데이터 기반이어야 설득력이 높음

## 결정 2. wide format을 long format으로 변환

- 문제: 원본 리뷰는 리뷰제목, 장점, 단점, 경영진에 바라는 점이 별도 컬럼으로 존재함
- 처리: `text_type`, `context_signal`, `review_text` 구조의 long format으로 변환
- 이유: 텍스트 유형별 맥락을 유지하면서 동일한 전처리/매핑 로직을 적용하기 위함

## 결정 3. 장점/단점/경영진 의견을 맥락 신호로 활용

- 문제: 긍·부정 단어 사전만으로는 리뷰의 방향성을 안정적으로 판단하기 어려움
- 처리: 장점은 positive context, 단점은 negative context, 경영진에 바라는 점은 improvement context로 정의
- 이유: 잡플래닛 리뷰의 입력 구조 자체가 텍스트의 방향성을 일부 제공하기 때문

## 결정 4. 표준화 사전 적용

- 문제: 같은 의미의 표현이 다르게 쓰이면 카테고리 매핑이 누락될 수 있음
- 처리: 표준화 사전을 적용해 표현을 통일
- 이유: 사전 기반 카테고리 매핑의 커버리지를 높이기 위함

## 결정 5. 사전 기반 카테고리 매핑 사용

- 문제: 리뷰 텍스트를 기업 단위 비교 지표로 사용하려면 카테고리 신호로 구조화해야 함
- 처리: 실제 카테고리 사전을 사용해 텍스트별 매칭 카테고리와 키워드 추출
- 이유: 어떤 표현이 어떤 카테고리에 매핑됐는지 설명 가능하다는 장점이 있음

## 결정 6. 커버리지와 미매칭 리뷰 확인

- 문제: 사전 기반 방식은 사전에 없는 표현을 놓칠 수 있음
- 처리: 카테고리 매칭률과 미매칭 리뷰 샘플을 별도 산출
- 이유: 전처리 결과의 해석 가능 범위와 한계를 명시하기 위함
