# 01 전처리 의사결정 로그

## 결정 1. raw / cleaned / ranking_view / unique_product 파일을 모두 사용

- 문제: 하나의 파일만 보면 전처리 전후 변화와 분석 단위 분리를 설명하기 어렵다.
- 처리: 원본 통합 파일, 기본 전처리 파일, 랭킹 기준 파일, 고유 상품 기준 파일을 모두 불러와 비교했다.
- 이유: 전처리의 핵심은 단일 결과물이 아니라 원본에서 분석용 데이터셋으로 바뀌는 과정이기 때문이다.

## 결정 2. 문자열 숫자형 변환 검증

- 문제: 크롤링 데이터의 가격, 원래가격, 할인율은 `13,730원`, `없음`, `35%`처럼 문자열 형태로 들어온다.
- 처리: 숫자 이외 문자를 제거하고 분석 가능한 숫자형으로 변환하는 과정을 재현했다.
- 이유: 가격 분포, 할인율, 리뷰 수 분석을 위해 수치형 변환이 필수다.

## 결정 3. ranking_view와 unique_product 분리

- 문제: 같은 상품이 여러 랭킹 기준에 반복 등장할 수 있다.
- 처리: 랭킹 화면 기준 분석용 `ranking_view_ecommerce.csv`와 고유 상품 기준 분석용 `unique_product_ecommerce.csv`를 분리했다.
- 이유: 랭킹 화면에서의 노출 구조와 플랫폼별 고유 상품 구성 분석은 기준 단위가 다르다.

## 결정 4. 품질 점검 파일 활용

- 문제: 전처리 결과가 의도대로 만들어졌는지 확인하지 않으면 분석 결과 신뢰도가 낮아진다.
- 처리: 랭킹 기준별 행 수, 순위 범위, 고유 product_key 수, 결측, 중복 여부를 확인했다.
- 이유: 전처리 후 데이터가 분석 가능한 상태인지 검증하기 위해서다.
